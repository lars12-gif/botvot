# Contest WhatsApp Bot — Euizhost / Node.js / Baileys

مشروع JavaScript يعمل على Node.js ويستخدم `@whiskeysockets/baileys` مع WhatsApp Multi-Device وPairing Code فقط. لا يوجد مسار QR مطبوع أو معروض. المشروع لا يستخدم Python أو Pydroid أو Termux.

> **مهم قبل النشر:** صفحة استضافة Euizhost تؤكد وجود حاويات لبوتات Discord ونشر من GitHub وبيئة Node.js 22. لكنها لا تثبت في المعلومات المنشورة أن WebSocket الصادر طويل الأمد مسموح لكل الحسابات أو أن ملفات `auth/` و`data/` تبقى عبر كل إعادة نشر. هذه النقطتان تحتاجان تأكيدًا من الدعم قبل ربط حساب واتساب. كما أن Euizhost يذكر أن التطبيق لا يعاد تشغيله تلقائيًا بعد انهياره؛ لذلك لا تعتمد على المشرف الخارجي وحده لإعادة تشغيل العملية.

## المتطلبات التقنية

- Node.js 22 (وهو الإصدار المعلن في استضافة Euizhost؛ وBaileys نفسه يتطلب 20+).
- npm 10 أو أحدث.
- عملية Node.js طويلة التشغيل تسمح باتصالات WebSocket الصادرة (السماح الفعلي يحتاج تأكيدًا من Euizhost).
- مساحة تخزين دائمة قابلة للكتابة لمجلدي `auth/` و`data/` (الاستمرارية بعد إعادة النشر غير مثبتة في الوثائق العامة التي راجعتها).
- اتصال إنترنت صادر إلى خدمات WhatsApp.
- لا يحتاج التطبيق إلى منفذ HTTP للاستقبال؛ الاتصال يبدأ من التطبيق إلى WhatsApp.

## إصدار Baileys

تم تثبيت `@whiskeysockets/baileys` على `7.0.0-rc14`، وهو الإصدار الموجود في مستودع Volcano المرجعي وقت الفحص، ويتطلب Node.js 20+. الإصدار مثبت بدقة بدل `latest` لتجنب تغيّر API تلقائيًا. كونه إصدار Release Candidate يعني أن تحديثه يجب أن يكون قرارًا واعيًا بعد الاختبار.

## التثبيت والتشغيل

```bash
npm install
cp .env.example .env
npm test
npm start
```

Start Command في لوحة الاستضافة: `npm start` أو `node src/index.js`.

لا يوجد `package-lock.json` مرفق لأن بيئة إعداد الحزمة لم تتمكن من الوصول إلى npm registry لإنشاء Lockfile موثوق. أنشئه على جهاز بناء متصل بالإنترنت عبر `npm install` ثم احتفظ به مع المشروع؛ لا تستخدم Lockfile يدويًا غير مكتمل.

## ربط واتساب لأول مرة

1. شغّل التطبيق من لوحة الاستضافة.
2. افتح سجل التشغيل الخاص والخاص بمالك السيرفر فقط.
3. عند ظهور `[PRIVATE PAIRING CODE]` انسخ الرمز المؤقت. لا تشاركه ولا تنشر سجل التشغيل.
4. على واتساب في الهاتف المرتبط بالرقم `+15879975734`: الأجهزة المرتبطة ← ربط جهاز ← الربط برقم الهاتف (قد تختلف التسمية حسب إصدار التطبيق).
5. أدخل الرمز الظاهر في سجل الاستضافة.
6. لا تعتبر الربط ناجحًا إلا بعد ظهور سجل `WhatsApp connection opened`.
7. بعد نجاح الاقتران تُحفظ بيانات المصادقة داخل `auth/`، ولن يطلب التطبيق رمزًا جديدًا طالما بقيت الجلسة صالحة.

Baileys يصدر حدث `qr` كإشارة داخلية في مسار الاقتران، ويستخدمه هذا التطبيق فقط لتوقيت استدعاء `requestPairingCode`. لا تتم طباعة QR أو عرضه أو استخدامه كطريقة ربط.

## الإعدادات والمسارات

رقم المالك موجود مرة واحدة في `src/config.js`:

```js
ownerPhone: '+15879975734',
ownerDigits: '15879975734'
```

لا يلزم تعديل الرقم في أي ملف آخر.

| المسار | الوظيفة |
|---|---|
| `auth/` | ملفات جلسة Baileys الحساسة |
| `data/groups.json` | إعداد مستقل لكل مجموعة |
| `data/flags-ar.json` | 250 مدخلاً محليًا للأعلام والأسماء العربية |
| `logs/` | مجلد مخصص للسجلات (لا يخزن محتوى الرسائل) |

يمكن ضبط `AUTH_DIR` و`DATA_DIR` إلى مسارات Volume دائمة من `.env` أو إعدادات الاستضافة. تأكد أن المجلدين خارج مساحة النشر المؤقتة إذا كانت الاستضافة تحذف الملفات عند إعادة النشر.

## أوامر المالك السرية

ترسل داخل المجموعة نفسها، ومن رقم واتساب المالك فقط:

| الأمر | الأثر |
|---|---|
| `💜طك` | تفعيل المجموعة الحالية فقط |
| `🍃شلع` | إيقاف المجموعة الحالية فقط |
| `*كتابة` | تعيين وضع writing |
| `*تفكيك` | تعيين وضع breaking |
| `*عكس` | تعيين وضع reverse |
| `*أعلام` | تعيين وضع flags |

كلها صامتة تمامًا. تغيير الوضع لا يفعّل المجموعة. تفعيل المجموعة لا يغيّر الوضع. المجموعات التي لم يفعّلها المالك لا تستجيب.

## صيغة المسابقة

المحتوى يجب أن يكون بين نجمتين، مثل `*هيسوكا*`.

- الكتابة: `*هيسوكا*` ← `هيسوكا`
- التفكيك: `*HELLO*` ← `H E L L O`
- العكس: `*HELLO*` ← `OLLEH`
- الأعلام: `*🇮🇶*` ← `العراق`

النص الداخلي يحافظ على المسافات. التفكيك والعكس يعملان على Grapheme Clusters باستخدام `Intl.Segmenter` حتى لا تتكسر الرموز التعبيرية المركبة.

## حفظ البيانات وتحديث المشروع

- إعدادات المجموعات تحفظ في JSON عبر ملف مؤقت ثم `rename` ذري، مع تسلسل عمليات الكتابة.
- جلسة Baileys تحفظ بواسطة `useMultiFileAuthState` في `auth/`.
- قبل التحديث: أوقف التطبيق، خذ نسخة احتياطية مشفرة وخاصة من `auth/` ونسخة من `data/groups.json`، حدّث ملفات الكود، ثم أعد التشغيل.
- لا ترفع `auth/` إلى Git أو ZIP عام، ولا تشاركها مع الدعم.
- لا تحذف `auth/` عند أخطاء الشبكة أو عند 401/403 بشكل افتراضي. إذا أعلن Baileys صراحة `loggedOut`، أعد الربط يدويًا بعد مراجعة الحساب.

## تصنيف الانقطاعات

- `restartRequired`: إعادة تشغيل Socket بتأخير قصير.
- `loggedOut`: يتوقف الاتصال ويطلب إعادة ربط يدوية؛ لا يمسح ملفات المصادقة تلقائيًا.
- `401/403/408/428/440/500` أو انقطاع غير معروف: لا يُفترض سبب واحد؛ تحفظ الجلسة ويعاد الاتصال بتأخير تصاعدي. راجع سجل الاستضافة وحالة الحساب إذا تكرر الخطأ.
- Pairing code لا يطبع إلا إذا نجح `requestPairingCode`؛ لا يوجد رمز وهمي.

## اختبارات

```bash
npm test
npm run check
```

الاختبارات تغطي دوال التحويل، Unicode، التحقق من المالك، استقلال المجموعات، الأعلام، الصمت، رفض أوامر العضو، منع التكرار وصيغة الإدخال. **هذه اختبارات منطق محلية فقط** ولا تثبت نجاح اتصال WhatsApp أو Pairing Code أو توافق خطة Euizhost. يجب إجراء اختبار اتصال حي من حساب المالك واختبار إعادة تشغيل/استمرارية التخزين على الخطة الفعلية.

## حدود التحقق الأمني

- يعتمد التحقق من المالك على PN JID المرفق بالرسالة أو PN البديل الذي يقدمه Baileys؛ رسائل LID التي لا يتوفر لها رقم هاتف موثوق تُرفض.
- لا يعتمد على اسم العرض أو رتبة المشرف.
- الرسائل الخاصة ورسائل البوت نفسه والرسائل غير النصية تتجاهل.
- لا تحفظ أرقام بقية الأعضاء أو نصوص الرسائل في قاعدة بيانات.
- حماية pairing code تعتمد كذلك على قفل صلاحيات لوحة الاستضافة وسجلاتها. اجعل سجل التشغيل خاصًا ولا تمنح مستخدمين آخرين صلاحية قراءته أثناء الاقتران.

## Euizhost: ما أمكن التحقق منه

صفحة استضافة Euizhost المنشورة تعرض:

| المعلومة | المجانية | المبتدئة | الاحترافية |
|---|---:|---:|---:|
| الذاكرة | 256MB | 1GB | 4GB |
| مساحة القرص | 500MB | 15GB | 50GB |
| بيئة التشغيل | Node.js 22 + Git | Node.js 22 + Git | Node.js 22 + Git |

وتذكر الصفحة أن النشر يتم بربط GitHub واختيار المستودع والفرع، وأن النظام يثبت الحزم ويكتشف أمر التشغيل من `package.json`. لذلك `npm start` مضبوط في هذا المشروع. لا يحتاج المشروع منفذ HTTP واردًا؛ هو ينشئ اتصالًا صادرًا إلى WhatsApp. كما لا يستخدم FFmpeg أو حزم معالجة وسائط أو مترجمات أصلية.

القيود المعلنة: لا تعيد Euizhost تشغيل البوت تلقائيًا عند انهيار العملية؛ يجب تشغيله من اللوحة بعد معالجة السبب. لذلك أعد الاتصال داخل البرنامج يعالج انقطاع WhatsApp ما دامت عملية Node قائمة، لكنه لا يعوض خروج Node أو قتل الحاوية.

ما لم أتمكن من إثباته من الصفحة العامة: السماح باتصال WebSocket صادر غير محدود، وبقاء الملفات بعد redeploy، ووجود Volume منفصل، وسياسة تخزين ملفات `auth/`، وأقصى مدة اتصال مستمر. مساحة القرص المعلنة لا تعني وحدها أن الملفات دائمة بعد إعادة النشر.

**التوصية:** لا أنصح بالباقة المجانية ذات 256MB لتشغيل Baileys دون اختبار ضغط؛ ابدأ باختبار على الأقل في بيئة 1GB، وراقب الذاكرة. قبل ربط واتساب، اسأل الدعم عن WebSocket الصادر وعن مسار دائم لا يتغير مع redeploy. إذا لم يوفروا ذلك، استخدم VPS/Node.js hosting يدعم التخزين الدائم والعمليات المستمرة.
